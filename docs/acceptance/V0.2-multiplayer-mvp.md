## 1. 范围

已验收当前最小多人多 Agent 对话平台：

```text
Project -> ProjectMember -> ProjectAgent -> 共享 Conversation
-> 用户选择 target_agent_id -> Run/Job/Lease
-> Conversation run.available SSE -> Project member Run SSE
```

诊断、能力缺口、匹配、Agreement、Trial、插件、文件、共享记忆和多 Run 并行均不在本版范围。

## 2. 验收场景

- Human A：`demo`，Project owner。
- Human B：`other`，Project editor。
- Agent 1：`演示 Agent 1`，属于 Human A。
- Agent 2：`演示 Agent 2`，属于 Human B。
- 两个人类与两个 Agent 位于同一个 Project 和同一个共享 Conversation。
- 两个独立 headless 浏览器实例分别登录两个人类；双方均可看到完整历史与双方目标 Agent 的回复，并实际订阅对方 Run 的 SSE。

## 6. 已知限制

- Conversation SSE 与 Run SSE 仍由 C++ 短周期查询 PostgreSQL 事件表推动；MVP 可接受，后续规模化时可评估数据库通知机制，但本轮不改变架构。
- 2.5 秒消息轮询保留为刷新和实时事件丢失兜底。
- Project 归档策略存在于最小 MVP PRD，但冻结 OpenAPI 没有归档路由，运行时也无入口；补齐需单独批准版本化契约变更。
- 同一 Project 写路径使用 Project 行锁串行化，MVP 规模可接受。
- 浏览器 E2E 需要本机 Edge/Chrome，未纳入无浏览器 Docker runner；API 2H+2A 已包含在 Docker-first 入口。
- 不支持多 Run 并行、Conversation 独立成员、消息编辑删除、Task/Handoff、文件、共享记忆、插件、诊断/匹配/Agreement/Trial。
- 生产部署仍需 HTTPS、正式账号管理、管理员/限流、备份、监控和 Worker 扩容。
